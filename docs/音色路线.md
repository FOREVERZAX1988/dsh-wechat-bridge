# 换音色：三条路线与当前状态

这台机器是 **1 核 2GHz、8GB 内存、无 GPU 的 VMware 虚拟机**，所以路线选择首要受算力限制。

## 已经在用的：云端零样本克隆（硅基流动 CosyVoice2）

```
文本 → POST /v1/audio/speech → mp3 → ffmpeg 转 24k wav → 播进 CABLE → 微信录音发送
```

- 一次合成 **0.7 秒**（4 秒音频）
- 克隆：`POST /v1/uploads/audio/voice` 上传 10~30 秒参考音频 → 拿 `speech:...` uri → 当 voice 用
- 配置：`语音后端=硅基流动`、`硅基流动密钥`、`克隆音色表`

**实测结论**：

| 参考素材 | 结果 |
|---|---|
| 日语原声 | 克隆出的中文带日语腔（韵律跟着参考语种走） |
| B 站唱段（demucs 分离后） | 合成一律 500（code 50507），克隆只吃说话素材 |
| 中文说话（145 条数据集） | ✅ 一次成功，中文自然 |

## 本机 RVC 换声（已验证，可跑但慢）

```
中文 TTS → RVC 推理换音色 → 发语音条
```

- 模型：HuggingFace 现成的 `.pth` + `.index`（不用训练）
- 实测 4.2 秒音频 **40 秒**（模型加载 25 秒 + 推理 15 秒）；常驻进程可压到 20 秒左右
- 环境：`~/.dsh/rvc-venv`（torch 2.6 CPU + transformers + demucs + yt-dlp）
- 转换脚本：`~/.dsh/rvc/rvc_convert.py`（feiyu-voice-toolkit 的纯 PyTorch 实现，绕开 fairseq）

**坑**（都踩过）：
- `rvc-python` 在 Py3.12 装不上（依赖老 numpy 源码编译）
- 模型 `sr` 字段是字符串 `"40k"`，`int()` 会崩
- 控制台 GBK 编不了 emoji → 设 `PYTHONIOENCODING=utf-8`
- f0 修正：RVC 的 `--pitch` 单位是半音，254Hz → 205Hz 约需 -4

## 训练路线（需要 GPU 机器）

数据集：`ModelScope: YinZilu/da-fei-yu-girl-voice-zh`（145 条中文语音，18 分钟，CC BY-NC 4.0）

准备脚本已跑通，产出在 `~/.dsh/rvc/gpt_sovits_ready/`：

```
wavs/            145 条 32kHz 单声道 16-bit
gpt_sovits.list  绝对路径|说话人|语言|文本
metadata.csv     原始标注
README-训练说明.md
```

打包：`~/.dsh/rvc/大肥鱼-GPTSoVITS训练包.zip`（55.5 MB）

**训练看这三步**（在 GPU 机器上）：
1. 装 GPT-SoVITS 整合包
2. 1A 格式化数据 → 1B 微调（SoVITS 8~10 轮 / GPT 10~15 轮）→ 1C 推理
3. 产物：`SoVITS_weights/*.pth` + `GPT_weights/*.ckpt` + 一条参考音频的文本

**训完怎么接**：
- 方案 A：把模型拷回本机，用 GPT-SoVITS 的 `api_v2.py` 本地跑（CPU 慢，一句十几秒到一分钟）
- 方案 B：模型留在 GPU 机器上跑 `api_v2.py`（默认 9880），本机发文字过去取音频（快）

桥接侧只需要一个「拿文本换 wav」的函数，两种方案接口一样。
